# Android interface

These native presentation contracts accompany the shared [product behavior](../product.md). State ownership belongs to [Android architecture](architecture.md), and read readiness belongs to [data loading](data-loading.md).

## Navigation and theme

Show the theme palette action only in the Home app bar. Learning, Records, and other destinations do not repeat this action; the selected theme still applies across the application.

Home is the navigation hub for Learning, Daily, and Records. There are no bottom tabs or expanded navigation rail; Learning and Records expose a labeled toolbar Back action to Home; daily selection opens in a dismissible sheet over Home. Keep visited workflow state without exposing inactive destinations to system or predictive Back. Put preferences and data controls behind clearly labeled actions.

## Home layout

Home uses the Web paper/teal palette and a tilted decorative Sudoku grid. Prioritize one hero with Start and optional Continue actions, followed by paired Daily/Learning cards and a quieter Records row. The complete entry hierarchy, including Continue when saves exist, fits one compact phone viewport at default font size. Preserve the mint hero surface, paper background, colors, corner radii, and secondary cards. Position the full hero-and-destinations group slightly above vertical center below the toolbar, distributing spare vertical space 40% above and 60% below. Inside the hero, put the kicker, two-line 26 sp / 38 sp heading, and 13 sp / 20 sp description together in one left-aligned column with 12 dp gaps. Center the tilted Sudoku artwork beside this entire column. The visual row has a 192 dp minimum height on regular-height windows; short windows wrap its content. Measure the copy at its natural width (capped at 65% of the visual row for enlarged text), leave an 8 dp gap, and give the remaining width to a square artwork region. Cap that region at 280 dp, or 112 dp in short landscape layouts that omit the description. Use the primary teal color for the kicker, matching the Web eyebrow. Render the rotated square at 92% of its available region using its geometric bounds; do not use a fixed board size or overflowing draw-scale enlargement. Put the full-width Start/Continue action row below both copy and artwork, separated by 20 dp, with 52 dp actions. Keep 20 dp hero padding and the existing paired Daily/Learning cards and Records row beneath it. Use columns on expanded windows. Large accessibility text may scroll instead of clipping controls or reducing the requested font scale. Preserve explicit setup confirmation and distinguish starting a new puzzle from resuming a stored one.

## Setup and resume

Free and daily setup open directly over Home as native modal bottom sheets. Adapt the Web information hierarchy to mobile rather than reproducing its desktop cards: six short variant labels occupy two rows of three touch targets at default phone text sizes, with a check mark and mint fill identifying selection. Show only the selected variant's rule summary; use a single segmented difficulty group for free play. Enlarged text uses fewer columns and scrolling. Daily options show their status, with the date, completion count, and an optional rules dialog. Keep one full-width primary action near the bottom safe area, plus a quieter continuation row and replacement warning when an unfinished free save exists. Provide an accessible Close action, scrim dismissal, and system Back. Opening or changing setup never starts or replaces a game; confirmation retains the existing free-save and daily formal/practice policies. Daily selection stays in its sheet rather than becoming an intermediate navigation destination.

When Home has multiple unfinished saves, Continue opens a native bottom sheet sharing the setup sheet's surface, width, drag handle, typography, close action, and focus behavior. Its header shows only the title and Close action, without a count subtitle or header divider. Use a flat list with fine dividers rather than filled cards: emphasize variant, place quieter difficulty beside it and a teal arrow at the trailing edge, show source in a small mint tag, and align filling progress/elapsed time with a quieter start timestamp in the footer. Keep horizontal text insets inside full-width clickable surfaces so press feedback reaches both sheet edges. Rows wrap naturally for enlarged text. Omit the start year only when it matches the current local year. Each full-row touch target shows variant and difficulty, source mode (including challenge date and formal/practice status for daily saves), filled player-entry cells out of original empty cells, elapsed time, and local start date/time. Filling progress does not assert correctness and excludes givens and notes. Sort newest-started first and allow scrolling without shrinking text. Selecting a row resumes that exact session; dismissal leaves all saves unchanged. A single unfinished save continues directly without the picker.

## Game and navigation

An active game is a focused destination with a top app bar, variant and difficulty, timer and pause, board, tools and number input. Leave through normal Android Back navigation, pausing and saving before another game is installed. Dismiss an open dialog or sheet before leaving its parent screen. The home-based navigation leaves full-board play free of persistent destination controls.

Use one reversible 240 ms scale-and-fade transition for page navigation. Toolbar Back, system Back, and predictive Back share the same return transform; a gesture seeks that transform instead of switching between the Navigation 3 default crossfade and a separate large shrink. Cancelling a gesture restores the current page without pausing or saving. On completion, keep the navigation preview at its last progress until the feature's save-before-leave guard succeeds, then finish the same animation. A failed save reverses the preview and leaves the error and retry on the current page. Keep the outgoing game presentation stable during saving and exit; do not insert preparation-cancellation text or a pause cover into the outgoing scene. Dialogs and sheets retain first refusal of Back, and Home leaves system back-to-launcher behavior available.

Keep Undo, Redo, Erase, Notes, Hint, and More readily available. More contains Check, Generate Candidates, Zoom, Settings, Restart, and New Game or Choose Another Challenge. Destructive replacement uses a dialog whose initial safe action is Cancel. A hint sheet shows each deduction and its board evidence, then an explicit Apply action. Pending conflict checks reuse the single-line board status area without changing the centered group height. Candidate generation has visible state; incomplete analysis never indicates a valid board.

Use a quiet centered title and difficulty, a timer immediately above the board, with rules in Settings and zoom in More, a compact six-tool strip, and two aligned input rows. Portrait board margins are 12 dp, with 6 dp additional inset around the input panel. Major board lines are 1 dp and givens use regular weight; entries keep medium weight. The primary row uses 52 dp tall outlined keys, 24 sp digits, and 4 dp gaps. The secondary row provides direct note toggles with smaller, quieter digits and an underline reflecting the selected cell's actual note mask. Direct note toggles use the same native edit queue and do not change the main keyboard input mode. Keep the existing Notes toggle for keyboard and primary-row entry. Prioritize a single nine-digit row using measured text widths, falling back to three columns only when necessary. Compact keys may be narrower than the recommended 48 dp touch width; zoom retains the full-size keypad. Tool labels similarly determine when reflow is needed. Omit routine input-mode, selected-coordinate, and successful-save captions; preserve save failures and retry. Position the board and controls as one group slightly above vertical center below the toolbar, using the same 40/60 distribution of spare space as Home. Leave 12 dp between the status row and board, and 16 dp between the board and input panel. Landscape uses adjacent board and controls. Short windows and large fonts can scroll. Board borders, region dividers, and givens share the controls' primary teal; minor grid lines use a lighter tint. Preserve semantic conflict and evidence colors, session ownership, pause, save, hints, and keyboard behavior. Conflicting cells use only the soft red background as their visual error indication: keep normal digit colors and omit corner error marks. Retain conflict descriptions and error semantics for screen readers; non-conflicting hint evidence keeps its existing marker.

## Loading and state

Prepare Home with a small Room bootstrap containing settings, dataset epoch, and unfinished-save presence. The first Home composition reuses it; neither native readiness, full save/history decoding, nor lesson content gates startup. Setup and Continue sheets read their own summaries, and returning Home refreshes only presence. Daily status uses today's six deterministic IDs and refreshes at the Beijing date boundary and on foreground. Preserve current data on ordinary refresh failure; clear personalized caches immediately after a dataset epoch change. Initial essential-storage failures keep the recoverable startup gate closed. See [Android Data Loading and Read Models](data-loading.md) for loading, migration and read contracts.

Reserve the game board square from the first composition, before a session exists. Loading, cancellation/retry, the paused cover, and the playable board share those exact bounds. Keep delayed preparation feedback inside the square and reserve the status line height even when the saved timer preference hides the timer, so data readiness cannot reposition the tools or number keys.

Defer transient progress indicators and loading captions until an operation has remained pending for 350 ms. Apply this presentation-only policy to app readiness, saved-game loading, game preparation, conflict checks, candidates, hints, records, and lessons. Cancel deferred feedback when work completes or the screen leaves composition; each new operation starts a fresh delay. Never delay work, navigation, completion, error feedback, or the actual disabled state of controls. Home retains its Start button while saves load, preserving its normal colors while it is disabled. After the first successful snapshot, background refreshes retain both Start and Continue actions, their colors, sizes, and labels; only their actual enabled state changes until the refresh finishes. Daily selection and its periodic refresh must not replace the home action row. The Records icon uses the same primary teal as the Daily and Learning icons. Game analysis uses the existing single-line board status area rather than adding rows below the keys.

## Adaptive layout and accessibility

Use available window size, not device labels or locked orientation, to choose layouts. Expanded windows place controls and explanations beside the board; Home places the hero beside its secondary entries. Landscape and split-screen layouts must keep the board square and every action reachable. Preserve the selected cell, input mode, course position, filters, and scroll position across navigation and configuration changes.

Map the existing light and dark palettes to semantic Compose theme tokens. Keep the Web teal primary action and blue-gray resume action; system dynamic colors do not replace these defaults. Use system Chinese fonts, stable-width timer digits, restrained motion, and one icon family. Common controls use Material 3; the specialized board does not inherit generic card or button styling.

Build the board from a semantic cell layer with custom clue drawing underneath it. A single Canvas without cell semantics is insufficient. Each cell exposes row, column, region where needed, fixed or entered value, notes, selection, conflicts, and relevant rule clues. Evidence includes text and shape markers as well as color. Support TalkBack traversal, external keyboard movement and shortcuts, enlarged text, reduced motion, and a zoomed board inspection mode with selected-cell details. Dense board cells are a documented geometric exception to the common-control target size; do not overlap 81 expanded hit regions. Compose semantics and touch behavior follow the [accessibility documentation](https://developer.android.com/develop/ui/compose/accessibility/semantics) and [API defaults](https://developer.android.com/develop/ui/compose/accessibility/api-defaults).

## Records

Records uses the existing paper/teal palette, standard app toolbar, and six-variant choice grid from Learning. A saveable Overview / Local Saves / Completion History tab separates the three reading tasks. Overview emphasizes formal daily streaks and assisted/unassisted totals in a mint card, followed by a compact free-play best-time table. Local Saves emphasizes the most recently started unfinished session, retaining all other saves and completed-session access; Completion History orders completed results by completion time and groups them by local calendar date. Dates are display-only; daily eligibility continues using the existing Beijing-date domain contract. Use actual supported variants and persisted facts, never preview sample data.

The toolbar Backup action opens a scrollable Material bottom sheet with export, file selection, quarantined-record cleanup when needed, and a separate destructive clear action. Restore and clear retain their existing explicit confirmation and safe initial focus. Keep errors and retry visible in the active sheet as well as the page, retain deferred progress presentation, and avoid displaying an empty-data summary before the first successful load. Preserve the selected tab and each variant/tab scroll position across navigation and recreation. Use adaptive grid columns and stacked record details for enlarged text; no background palette action is added outside Home.

## Learning directory and lessons

The Learning directory uses the existing paper/teal theme and a compact mobile hierarchy: overall course progress, all six variant choices in two rows of three, one mint recommended-lesson card, and a continuous list of full-row lesson targets. The list uses course-local numbering, check marks and explicit labels for completed lessons, and a distinct in-progress label. Recommend the selected course's unfinished current lesson, otherwise its first unfinished lesson, or its first lesson for review when complete. Read stage numbers from the catalogue-restored cursor; recommendations never mutate progress. Keep all lessons freely accessible and preserve the existing lesson/exercise workflow and Chinese authored content. Use at least 48 dp variant/action targets, adapt the choices to fewer columns at large font scales, and allow vertical scrolling. Bound the directory to 640 dp on wide windows. Keep one primary Start/Continue/Review action; lesson rows open directly without repeating a button on every card.

The lesson screen separates Learning Explanation and Hands-on Practice with two selectable tabs. Use a compact lesson toolbar, a mint principle card, the authored example board and explanation, and a fixed bottom primary action. Practice shows its current stage, a reserved feedback region, the interactive board, a single row of outlined digit keys when space permits, and a secondary Clear action. Use the same Material top-app-bar height and titleMedium typography as the other destinations, including the game. Keep the tabs outside scrolling content. Both modes share a measured-height message card followed by an equal-height board heading and the same board bounds. Preserve the shared scroll offset and its visited content extent so switching to a shorter mode cannot clamp the offset. Separate the Clear icon and label by 8 dp. Switching tabs preserves the unfinished answer; a correct saved submission still requires explicit Next. Keep long authored explanations scrollable without moving the board on feedback changes. Put board zoom and full-board practice in the toolbar menu, retain a labeled zoom action beside the guided example, and explain that full-board practice does not complete the lesson. Hide solution evidence during an unanswered exercise and reveal it with correct feedback. Use shared theme tokens, safe drawing insets, and scrollable content on short windows and enlarged text.

Game entry and lesson practice share the same light-surface digit keys: 8 dp corners, a thin teal outline, 24 sp digits, 52 dp minimum height, and a mint press state. Prefer nine keys in one row, using measured text width to fall back to three columns when needed. Zoomed boards retain wider targets. Keep the game's independent quick-note row and its existing actions.

Unknown personal progress has no recommendation action. Reserve the recommendation region from authored content at the current width and font scale so progress arrival cannot move the course heading or first lesson. Sizing-only content has no focus targets or personal facts. Preserve explicit submission, durable advancement and first-completion semantics.
